ENV准备环境

本地起一个这个分支的 phi-agent（端口 8788），再把这个分支的 Sidecar 加载进 Phi Canary 并让它连本地 phi-agent。命令都在仓库根目录执行，除非写了 cd。

  1. 确认前置条件

    • macOS，已安装 Phi Canary（/Applications/Phi Canary.app），并用公司测试账号登录（stag 环境，登录走 auth.stag.phibrowser.com）。
    • 退出 Phi 正式版。本地 phi-agent 要连 Canary 的 Runner 和浏览器通道，两个浏览器都开着时容易连错。
    • Docker Desktop 已运行（提供 Postgres）。
    • 测通知卡片（N 节）要用较新的 Canary：2026-10-08 在 Canary 154 上实测可用。
    • Node 24（仓库钉的是 24.14.0，20 以上能用）和 pnpm 10.17.1。
    • 网络能访问 ai-service.stag.phibrowser.com（模型）和测试网站 https://woodnotfound.github.io/phi-watch-test-pages/。
    • 知道会发生什么：加载 Sidecar 会重启 Canary，影响所有 Profile（包括 Phi Chat 窗口），先保存草稿、结束进行中的对话；测完换回商店版没有自动步骤（见「收尾」）。
    • 本地 phi-agent 用独立的数据库，对话列表一开始是空的。Canary 原来的对话不会出现，也不会被改动。
    node -v
pnpm -v
docker info --format '{{.ServerVersion}}'

  2. 取代码并安装依赖

    被测分支 feature/task-conversation-link-v2，最新提交 bb94df778，基于 staging e96accd69，共 42 个提交。分支目前只在 Wood 本机，还没推送；推送后其他人先 git fetch。

    cd ~/Sources/FydeOS/phi-ai
git switch feature/task-conversation-link-v2
git log -1 --oneline
pnpm install

    预期：git log 输出以 bb94df778 fix(sidecar): a task's report strips and its panel switch share one state 开头。

  3. 准备数据库和 phi-agent 配置

    用仓库自带的 compose 起一个 Postgres（容器 phi-memory-pg，端口 5432，用户和密码都是 phi）。phi-agent 启动时会自动建库建表，库名随意。已有别的 Postgres 也可以用。

    docker compose -f phi-memory/docker-compose.yml up -d --wait

    没有 phi-agent-dsh/.env 就从模板复制一份；已有的话只改 POSTGRES_URL：

    cp phi-agent-dsh/.env.example phi-agent-dsh/.env
    POSTGRES_URL=postgres://phi:phi@127.0.0.1:5432/phi_agent_manual

    其余保持模板默认：OPENAI_BASE_URL 指向 stag ai-service，AUTH0_DOMAIN=auth.stag.phibrowser.com，ENABLE_LOOPBACK=true 打开 8788 端口。OPENAI_API_KEY 留空即可：带 PHI_SENTINEL_UNMANAGED=1 启动时，模型调用直接发到 ai-service，用 Runner 发的 token。

  4. 构建并加载 Sidecar（会重启 Canary）

    build:local 把 Sidecar 指向 http://127.0.0.1:8788（配置在 deployment/env/local/ai-sidebar.env）。加载脚本把 dist 复制成一份快照，再用 --load-extension 重启 Canary。先 --dry-run 看计划，确认后再正式执行。

    pnpm --filter @phi-ai/sidecar build:local
    bash scripts/load-phi-canary-plugins.sh --sidecar-only --dry-run
    bash scripts/load-phi-canary-plugins.sh --sidecar-only --quit-existing

    预期：输出 Sidecar snapshot: ~/.local/state/phi-debug/sidecar-load/load.XXXXXX/extension 和 Loading Sidecar: …，Canary 正常退出后重新打开，并打开 Phi Chat 窗口。

    不要加 --build：它会按正常配置重新构建，Sidecar 就不连本地了。改了 Sidecar 代码要重新 build:local 再跑加载脚本，快照不会自己更新。

  5. 找到 Canary 的 Runner socket

    Canary 每次重启，Runner 的 socket 路径都会变，所以这一步放在加载 Sidecar 之后。以后只要重启了 Canary，就重新找一次，并重启 phi-agent。

    pgrep -f 'Phi Canary.app/Contents/Library/LoginItems/.*MacOS/runner'
    lsof -a -p <上一步的 PID> -U -Fn | grep 'runner.sock$'

    预期：输出一行 n/tmp/phi-sentinel-<hash>/runner.sock，去掉开头的 n 就是路径。

  6. 启动 phi-agent（保持这个终端开着）

    cd phi-agent-dsh
RUNNER_SOCKET=/tmp/phi-sentinel-<hash>/runner.sock PHI_SENTINEL_UNMANAGED=1 TMPDIR=/tmp pnpm dev:self-hosted

    预期：先生成 rows 表，然后出现 Starting phi-agent server on 127.0.0.1:8788。第一次启动会自动建库 phi_agent_manual。另开一个终端检查端口：

    curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8788/health

    返回 401 就说明服务在（/health 需要登录）。没有 RUNNER_SOCKET 时任务运行和定时触发拿不到 token，会失败。

    停止：在这个终端按 Ctrl-C。如果 8788 仍被占用，用 lsof -ti tcp:8788 -sTCP:LISTEN 查到 PID，再 kill 这个 PID。

    平时用 pnpm dev:local 的也可以：它同时起 Postgres、phi-memory 和 phi-agent（phi-memory 需要自己的 phi-memory/.env），phi-agent 同样在 8788。两个服务都开着 Phi 正式版时，要用 RUNNER_SOCKET=… pnpm dev:local 指定 Canary 的 socket。

W-07P1

「盯到什么时候」的三种回答

前置分三次走完整流程（可以用三个测试页同时做）。

步骤
  1. 第一次回答一个日期，比如「到 10 月 31 日为止」。
  2. 第二次回答一个条件，比如「降到 50 以下就不用再看了」。

  4. 每次建好后打开任务面板看。
预期
  • 只给日期：面板显示「截止到 …」，没有停止条件。
  • 只给条件：面板显示「停止条件：…」，没有截止。
  • 两个都给：两行都有。
  • 跳过这一问时，任务一直运行到你让它停。

T测试网站场景

测试网站 https://woodnotfound.github.io/phi-watch-test-pages/（仓库 WoodNotFound/phi-watch-test-pages）有 23 个虚构的页面，每个页面的内容按时间分成几个阶段，scenarios.json 是标准答案。链接里的 t0 是开始时间（毫秒），step 是每个阶段多少秒。页面每次加载时按当前时间算出阶段，之后不会自己变（只有 live-ticker 每 3 秒刷新）。不带 t0 时从当天 UTC 零点算起，通常已经在最后一个阶段，所以一定要用「测试链接生成器」生成链接。

每个页面都有中文和英文两种语言，用 lang=zh 或 lang=en 切换；不带时用页面自己的语言（zh-price 是中文，其余是英文）。两种语言下数字、价格、货币和阶段完全一样，所以下面的标准答案对两种语言都成立。品牌、产品型号、人名、书名、地名和货号保留原文。表格里的请求给了中文说法，后面小字是答案里的英文原文。

做法

  1. 在「测试链接生成器」里选场景和页面语言，step 用 300（每阶段 5 分钟），点「用现在的时间生成」，在新标签页打开「给 agent 关注的链接」。每个场景卡片上的「用生成器生成链接」会直接跳过去。
  2. 在这个页面上右键「让 Phi 关注此页面」。第一问回答表格里的某个请求（用中文说同样的意思也可以）；频率选「每 30 分钟」；汇报格式跳过；测停止条件时，最后一问回答停止条件，否则跳过。
  3. 建好后在任务面板点「暂停定时」，免得定时运行打乱节奏。测停止条件的场景不要暂停。
  4. 马上「立即运行」一次，这是第 0 阶段的基准。
  5. 之后每进入一个新阶段（生成器显示当前阶段和倒计时）就「立即运行」一次，等面板显示「已完成」。一次运行大约一两分钟（估算），所以 step 不要小于 180。
  6. 每次运行后对照表格：这个阶段是「汇报」的，对话里要有新汇报并说出新值；「不报」的，对话里不能有新消息。
  7. 跑完说「删除这个任务」。同一阶段多跑一次应该不报，正好可以顺便测 R-02。
基准 第一次检查，说出当前值汇报 要在对话里发汇报不报 不发消息可报 发不发都对，带 * 的悬停看说明读不到 可以说读不到，不能说值变了— 还没开始关注

未读蓝点

前置有一条在你不在对话时送到的汇报（R-06）。

步骤
  1. 看列表。
  2. 打开这个对话，再切到别的对话。
预期
  • 标题前有蓝点、标题加粗（读屏为「未读」）。
  • 正打开的那一行从不显示蓝点；离开后也不再出现，除非又有新汇报。
  • 多选模式下，蓝点的位置让给勾选框。
L-02P0

按最后活动排序

前置列表里有 3 个以上对话。

步骤
  1. 在最下面那个对话里发一条消息。
  2. 给另一个对话改名，或改它的分类。
  3. 让某个任务汇报到一个靠下的对话。
预期
  • 发消息的对话排到最上面，行上的时间是最后活动时间。
  • 改名、改分类不会把对话顶上去。
  • 收到汇报的对话排到最上面。
L-03P0

时钟图标和「任务」视图

前置有 2 个带任务的对话、若干普通对话。

步骤
  1. 看列表行。
  2. 打开筛选菜单。
  3. 选「任务」。
  4. 删掉其中一个对话里的全部任务，切换窗口回来或等 30 秒。
预期
  • 有任务的对话在标题后显示时钟图标（读屏为「有定时任务」）。
  • 筛选菜单里「全部」下面是「任务」，带数量 2。
  • 选「任务」只显示这 2 个对话。
  • 删完任务的对话离开「任务」视图，数量变成 1。
L-04P0

一个对话放进多个分类

前置已有分类 A、B。

步骤
  1. 在一行的「···」里打开「分类」，勾 A，再勾 B。
  2. 分别筛选 A 和 B。
  3. 把 A、B 都取消。
  4. 在子菜单底部「新建分类」建一个 C。
预期
  • 勾选立刻生效，菜单不关。
  • 这个对话同时出现在 A 和 B 下。
  • 都取消后它算未分类。
  • 新建的分类出现在菜单里，可以直接勾选。
  • 对话顶栏菜单里的「分类」子菜单行为一样。
L-05P1

多选后批量改分类（三态）

前置3 个对话：一个在 A，一个在 A 和 B，一个都不在。

步骤
  1. 点「选择」，勾这 3 个对话，打开选择栏的「分类」。
  2. 点 A。
  3. 再点 A。
  4. 点「移出所有分类」。
预期
  • 打开时：A 显示减号（部分有），B 显示减号，其他不勾；有计数。
  • 第一次点 A：3 个都加上 A，A 变成勾。
  • 再点 A：3 个都移出 A。
  • 「移出所有分类」后 3 个都是未分类。
L-06P1

删除分类

前置一个对话在 A 和 B，另一个只在 A。

步骤
  1. 删除分类 A，读确认框，确认。
预期
  • 确认框写着：对话会保留其他分类，不再属于任何分类的对话会移到「…」。
  • 第一个对话还在 B 下；第二个移到确认框里说的那个分类。
L-07P2

分类改不了时回滚

前置停掉 phi-agent。

步骤
  1. 给一个对话勾一个分类。
  2. 启动 phi-agent。
预期
  • 勾选退回原状，提示「无法更新分类」。
  • 服务回来后再勾能成功。

B对话基本行为

这次一起修的两处聊天行为。

B-01P0

开始做事时只回一句

前置侧边栏打开，当前标签页是任意网页。

步骤
  1. 发「把这个页面加到书签栏」。
  2. 看 agent 的第一条回复，以及后面的结果。
预期
  • 第一条回复只有一句，说它要开始做（比如「好的，我来加到书签栏」）。
  • 第一条回复里不提前说「已加好」这类结果。
  • 结果在后面单独告诉你，和实际一致。

测完删掉这个书签（也可以和 C-06 一起做）。

B-02P0

Stop 立即结束

前置新对话。

步骤
  1. 发「写一篇 2000 字的文章介绍浏览器的历史」。
  2. 输出到一半点 Stop。
  3. 马上发下一条消息。
预期
  • 点下去输出立刻停住，后面不再追加文字。
  • 按钮立刻变回发送，下一条消息正常回复。
B-03P1

浏览器任务中途 Stop

前置新对话。

步骤
  1. 发一个需要操作浏览器的请求（比如「打开测试网站首页，把场景名称列给我」）。
  2. 它开始操作后点 Stop。
  3. 再发「继续」。
预期
  • 任务停下，没有残留的「正在执行任务」状态。
  • 之后对话正常。

X服务重启

phi-agent 在任务运行中途重启。重启 phi-agent 时 Canary 不用动；但如果重启了 Canary，要按第 5 步重新找 socket。

X-01P0

运行中重启：重新排队一次

前置有一个关注任务。

步骤
  1. 「立即运行」，等面板显示「运行中」。
  2. 马上在 phi-agent 终端 Ctrl-C，用同一条命令重新启动。
  3. 等 1 到 2 分钟，看面板、对话和「Shadow 任务」页。
预期
  • 启动后不到半分钟，这次运行重新排队并重新开始，不用等运行超时。
  • 「Shadow 任务」的日志里有一行 Queued again: the agent service restarted while it ran。
  • 重新开始时立刻打开隐藏窗口，没有两分钟左右的卡顿。
  • 运行正常结束，对话里正常汇报。

重启后侧边栏可能要等你发下一条消息才重新连上，这不算问题。

X-02P1

再次重启：停下并说明原因

前置接 X-01，在重新开始的那次运行里。

步骤
  1. 运行中再重启一次 phi-agent。
  2. 等它启动后看面板和对话。
预期
  • 这次运行变成「失败」，不再重新排队。
  • 对话里汇报（红色「失败」），说明服务在运行中重启、已经重试过一次所以停下，不说「重新排队」。
  • 「Shadow 任务」里的错误是 The agent service restarted while this run was in progress. It had already been retried once, so it was stopped instead of being retried again.
X-03P1

重启后定时照常

前置有一个每 30 分钟的任务，记下面板里的下次运行时间。

步骤
  1. 在两次运行之间重启 phi-agent。
  2. 等到下次运行时间。
预期
  • 下次运行时间不变，到点照常运行和汇报。
X-04P2

汇报补发

前置有一个关注任务，汇报方式「每次都汇报」。

步骤
  1. 「立即运行」，盯着面板，状态一变成「已完成」就重启 phi-agent。
  2. 启动后等 1 分钟。
预期
  • 这次运行的汇报在重启后补到对话里，只出现一次。

时间不好卡，汇报在重启前已经送到也算通过，记一下实际情况。

·不在手测范围

  • 维护扫描改成一次查询读全部运行（性能改动，看不到界面变化；存储和任务包的自动化测试覆盖）。
  • 回复里的工具调用一直不结束时的处理（靠回放测试覆盖，手工很难造出来）。
  • Langfuse 里任务运行的追踪内容，包括通知卡片的判断（task.report_card，开发自查用）。
  • 通知卡片判断用的阈值（0.5）是否合适：靠重放真实判断来校准，手测只看 N 节的行为。
  • Sentinel 任务页的「对话」按钮、帮助中心同步（不在这个仓库）。

·收尾

  1. 在每个测试对话里说「删除这个任务」，或者新开对话问「我有哪些定时任务」再逐个删除。在「Shadow 任务」页确认没有还在定时的任务。
  2. 删除测试书签（B-01、C-06）。
  3. 停 phi-agent：在它的终端按 Ctrl-C。
  4. 可选：删除测试库并停掉 Postgres。
    docker exec phi-memory-pg dropdb -U phi phi_agent_manual
    docker compose -f phi-memory/docker-compose.yml stop
  5. Canary 里加载的是本地 Sidecar，它只连 8788：phi-agent 停了以后侧边栏不能聊天。直接退出 Canary 再正常打开，不一定回到原来的商店版 Sidecar（命令行加载会改写扩展注册，可能缺失或版本不对）。在 chrome://extensions 看 Sidecar 的来源；要回到商店版，按 docs/local-development.md 的「Hidden Phi Chat Profile」一节做。
  6. 确认没有浏览器在用之后，可以删掉 ~/.local/state/phi-debug/sidecar-load/ 下的快照目录。
